# ScratchWWW local account pages and project storage

This build includes local replacements for the Scratch 2.0-era pages that are not part of the open ScratchWWW frontend.

## Pages

- `GET /users/:username/`: public profile, bio, status, country and shared projects.
- `GET /mystuff/`: signed-in user's project list, shared/unshared filters, and share/unshare controls.
- `GET /accounts/settings/`: profile, email, password and logout settings.

The pages use the same `local_session` cookie and `dev-server/local-data/accounts.json` account store as the local ScratchWWW authentication endpoints. Profile fields are saved to that account record and synchronized to an existing linked Sit identity when one exists.

## Project storage

The development server defaults `PROJECT_HOST` to `/projects-data`.

- `POST /projects-data/` creates a project and returns `content-name`.
- `PUT /projects-data/:id` updates an owned project.
- `GET /projects-data/:id` returns an SB3 ZIP containing `project.json` and the referenced assets fetched from `ASSET_HOST`.
- `/scratch-api/projects/:id` returns the project metadata expected by the ScratchWWW preview.

Project metadata is stored in `dev-server/local-data/projects.json`. Do not edit this file while the server is running.

## Configuration

Optional environment variables:

- `PROJECT_HOST=/projects-data` (default for the local server)
- `ASSET_HOST=https://assets.scratch.mit.edu` (default)
- `SITHUB_DATA_DIR` (optional custom Sit data directory)

## Validation

`node --check` passed for the new page module, server entry point, storage helper, and Webpack config. A full Webpack build and browser test still need to be run after installing the root dependencies with `npm ci`.
